How SpamShield Works: Architecture & Explainability

Educational breakdown of Natural Language Processing, TF-IDF vectorization, Multinomial Naive Bayes, and Explainable AI.

System Architecture & Data Flow

End-to-end pipeline from raw SMS/email input to model inference, explainability attribution, and threat mitigation.

📩
1. Input Preprocessing
Regex normalization of URLs, emails, phone numbers, and currencies ($ / Rs / INR).
🧮
2. TF-IDF Vectorization
Converts text into 5,000 statistical n-gram features (unigrams & bigrams) with sublinear scaling.
🤖
3. ML Classification
Multinomial Naive Bayes computes class likelihoods P(Spam | Message) with Laplace smoothing.
🔍
4. Explainable AI & Rules
Extracts token log-odds differences, highlights high-risk words, scans URLs, and assigns categories.

1. What is TF-IDF?

TF-IDF stands for Term Frequency – Inverse Document Frequency. In machine learning, computers cannot directly read words, so we must convert sentences into numerical feature vectors.

  • Term Frequency (TF): Measures how frequently a word appears inside the current message. If a word like "winner" appears 3 times in an SMS, its TF score is high.
  • Inverse Document Frequency (IDF): Penalizes universally common words like "the", "is", or "at" that appear everywhere, while amplifying rare, high-signal words like "kyc", "blocked", or "crorepati".
TF-IDF(t, d) = TF(t, d) × ln[(1 + N) / (1 + DF(t))] + 1

2. Why Multinomial Naive Bayes?

Naive Bayes is a probabilistic classifier based on Bayes' Theorem with the "naive" conditional independence assumption between features.

P(Spam | Message) ∝ P(Spam) × ∏ P(word_i | Spam)
  • Why it excels for spam: Word presence distributions are heavily skewed (words like "claim", "prize", "urgent" have astronomically higher probability in spam).
  • Laplace Smoothing (α = 0.1): Prevents zero-probability problems when a test message contains a word not present in a specific class during training.
  • Speed & Efficiency: Inference takes under 2 milliseconds on standard CPU hardware without GPU acceleration or cloud API dependencies.

3. Explainable AI (XAI) Implementation

Instead of presenting the user with an inscrutable "black box" prediction, SpamShield calculates token-level attribution scores:

Log-Odds Impact(w) = log P(w | Spam) - log P(w | Ham)

When this value is positive, the token statistically pulls the prediction towards Spam. SpamShield normalizes these values to dynamically scale the red highlight opacity in the browser, providing transparent insight into why the message was flagged.

4. Cybersecurity Link Scanner Heuristics

Phishing attacks rely on fraudulent destination URLs. SpamShield's regex parser dissects every embedded hyperlink and evaluates:

  • Raw IP addresses: Legitimate financial portals use accredited domains, never raw IPs like 192.168.1.1.
  • High-Risk TLDs: Domains registered under disposable or abuse-prone TLDs (.xyz, .top, .buzz).
  • Shortened Links: Obfuscated redirects via bit.ly or tinyurl concealing actual landing servers.
  • Credential Theft Keywords: Subdomains containing kyc, verify, or netbanking on third-party hosts.

College Viva Voce / Presentation Q&A Cheatsheet

Prepare for your viva presentation with these common external examiner questions and succinct answers.

Q1: Why did you choose Multinomial Naive Bayes over deep learning (e.g. LSTM / BERT)?

Answer: For short text like SMS messages (average 15-30 words), TF-IDF with Multinomial Naive Bayes achieves 98.84% accuracy with near-zero latency (<2ms) and runs on lightweight server hardware without GPU requirements. Deep transformers like BERT require heavy memory, slower inference, and significant training data to avoid overfitting on short text.

Q2: How does the application solve the "Black Box" problem of Machine Learning?

Answer: We implemented Explainable AI (XAI) using log-odds likelihood ratios. By extracting the log-probability differences between spam and ham classes for every token, SpamShield highlights exactly which words pushed the classification toward spam with variable color intensity and shows the top 5 trigger keywords.

Q3: What was the motivation for augmenting the UCI SMS dataset with Indian scam examples?

Answer: The classic UCI SMS dataset (from 2012) primarily features UK/Singapore text. Modern attacks in India target regional contexts like SBI YONO KYC updates, KBC lottery draws, electricity bill disconnections, and fake work-from-home tasks. Augmenting with indian_scams.csv ensures the model recognizes these modern localized fraud patterns.

Q4: How did you prevent False Positives on legitimate banking SMS?

Answer: We trained on balanced legitimate banking communications (such as genuine OTPs, monthly statements, and delivery confirmations) alongside scam messages. Scam messages almost always combine urgency with unverified external URLs or phone numbers to contact, whereas legitimate bank OTP alerts advise users never to share the code.
